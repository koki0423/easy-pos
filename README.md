# 簡単POS

商品を選んで合計を確認・確定できる、シンプルなWeb POSアプリです。イベントごとに商品設定・在庫・会計を分けて管理できます。

## 起動

```powershell
go mod tidy
go run . --deploy
```

ブラウザで `http://localhost:8080` を開きます。引数なしの `go run .` は、誤って売上データを作らないようUsageを表示して終了します。

### 起動モード

- `go run . --deploy`: 本番モード。最初にWeb画面で使用するイベントDBを選択します。選択したDBへ売上・在庫を保存し、正常終了時に対応する商品YAMLへ現在の設定と在庫を書き戻します。
- `go run . --debug`: デバッグモード。`pos-debug.db` を使用し、Ctrl+Cで正常終了したときに初期化します。
- `go run . --test`: テストモード。`pos-test.db` を使用し、Ctrl+Cで正常終了したときに初期化します。

`--debug` と `--test` は起動時も空のDBから始まるため、操作中は売上ログを確認でき、Ctrl+Cで止めれば次回に持ち越しません。これらのモードでは `products.yaml` も変更しません。電源断や強制終了では自動削除を保証できませんが、次回の同モード起動時に初期化されます。`--deploy` の既存売上データは削除しません。

### イベントDBの選択

`--deploy` でブラウザを開くと、POS画面の前にDB選択モーダルが表示されます。

- **新規作成**: 英数字・`-`・`_` のイベント名を指定すると、`events/<イベント名>/pos.db` と、商品0件の `events/<イベント名>/products.yaml` を作成します。作成直後は設定ページが開くため、イベント固有の商品を登録してからPOSを使います。
- **既存のDBを読み込み**: `events` 内のイベントDBを選ぶと、対応するYAMLと在庫・会計履歴を再開します。既存の `pos.db` は「既定の pos.db」として選択できます。

終了時には、選択したイベントのYAMLへ商品・セット割引・監査出力先・現在庫（0を含む）が保存されます。イベントごとのデータは混在しません。ルートの `products.yaml` は `--test` 用および既定DBの参照用として保持し、本番イベントの終了時に書き換えません。

## 商品・セット割引の設定

本番モードで起動中は、POS画面右上の **設定** を押すと開く `settings.html` から商品とセット割引を編集できます。設定ページの「レジに戻る」でPOS画面へ戻れます。

- 商品は追加・修正・削除できます。削除は販売中の商品一覧と次回のYAMLから外すだけで、過去の会計・在庫履歴は残ります。セット対象になっている商品を削除すると、そのセットも外れます。
- セット割引は、対象商品・数量・セット価格を指定して追加・修正・削除できます。
- 設定内容はすぐPOS画面に反映されます。本番モードをCtrl+Cなどで正常終了すると、商品・セット割引・監査出力先と現在庫を選択中イベントの商品YAMLに保存します。**在庫0の商品も必ず保存されます。**

新規イベント作成時は商品0件のYAMLを生成し、店舗名・通貨だけをルート `products.yaml` から引き継ぎます。既存イベントでは対応する `events/<イベント名>/products.yaml` を読み込みます。ルートの `products.yaml` は変更しません。初回設定やPOSを起動していないときの編集には、イベント配下のYAMLを直接変更することもできます。セット割引は商品の内側ではなく、トップレベルの `set_discounts` に定義します。

```yaml
products:
  - id: coffee
    name: ブレンドコーヒー
    unit_price: 450
    initial_stock: 20
  - id: croissant
    name: バタークロワッサン
    unit_price: 320
    initial_stock: 12

set_discounts:
  - id: morning-set
    name: モーニングセット
    items:
      - product_id: coffee
        quantity: 1
      - product_id: croissant
        quantity: 1
    set_price: 700
```

上記は「コーヒー1点とクロワッサン1点を700円」にする例です。同じ商品のまとめ買い割引も、`items` に同じ商品を必要数だけ指定して表現できます。複数のセットが競合したときは、商品を二重に使わず、合計の割引額が最も大きくなる組み合わせが自動適用されます。YAMLを手で変更した場合だけ、読み込みのために再起動してください。

## 在庫管理

各商品の `initial_stock` は、初めて起動する際の在庫数です。本番モードを終了すると、この値はSQLite上の現在庫で更新されます（在庫0も含みます）。既に登録済みの商品のYAML上の在庫を直接変更しても、SQLiteの現在庫は上書きされません。

起動後は商品カードの「在庫を管理」または設定画面の商品編集から在庫数を直接更新できます。会計が確定すると在庫が自動で減り、在庫を超える数量は追加・会計できません。実在庫の棚卸しや補充には画面の更新機能を使用してください。

## 売上ログ

画面右上の「売上CSVを出力」から、会計ID・日時（JST）・商品・数量・金額・適用セット・取引種別・変更理由をCSVでダウンロードできます。先頭にはイベント名と出力日時、末尾には取消・返品を反映した商品別の純販売数と合計売上額を出力します。画面内には直近10件の会計履歴も表示されます。ログはSQLiteに保存されるため、アプリを再起動しても残ります。

設定画面の「会計監査出力」では、任意の出力先ディレクトリを指定し、「今すぐ監査CSVを出力」で同じ会計監査CSVをそのディレクトリにファイルとして保存できます。指定した出力先は次回本番起動時にも使えるようYAMLに保存されます。

同じ画面の「運用監査CSVを出力」では、手動在庫更新、商品追加・変更・削除、セット割引変更、監査CSV出力先変更を別CSVに出力できます。各記録には日時・対象・操作種別と、変更前後の値がJSON形式で残ります。

## 取消・返品・訂正

未確定のカートは、通常どおり数量の変更・商品の削除で修正できます。会計確定後は会計履歴の「取消・訂正」から処理します。

- **取消**: 支払い・商品受け渡し前の誤会計を取り消します。
- **返品・返金**: 支払い・商品受け渡し後の会計を返品・返金として記録します。
- **訂正して再会計**: 元会計を取消として記録した後、元の内容をコピーした新しいカートを開きます。内容を直して会計を確定してください。

確定済み会計は削除・更新されません。取消・返品・訂正は、元会計と反対金額の取引、在庫復元、`sale_adjustments` の追記として保存されます。訂正後の会計IDも元会計に紐付き、CSVにはすべての取引が残ります。訂正カートを閉じてしまった場合も、履歴の「訂正を再開」から再び開けます。

## 環境変数（任意）

- `PORT`: 待受ポート（既定値: `8080`）
- `PRODUCTS_FILE`: `--test` と既定DBが参照する商品YAML。新規イベントは店舗名・通貨だけを読み取ります（既定値: `products.yaml`）
- `DATABASE_FILE`: 既定イベントとして読み込める従来のSQLiteファイル（既定値: `pos.db`）
- `EVENTS_DIR`: イベント別のDB・YAMLを保存するディレクトリ（既定値: `events`）
- `DEBUG_DATABASE_FILE`: `--debug` 用SQLiteファイルのパス（既定値: `pos-debug.db`）
- `TEST_DATABASE_FILE`: `--test` 用SQLiteファイルのパス（既定値: `pos-test.db`）
